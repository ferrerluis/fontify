# Bunvale 0.016 — private review build

Bunvale is the selected Cooper Black B modernization: a warm, heavy display serif with swelling strokes, soft feet and lively oval counters. Its selected uppercase and lowercase letterforms are preserved.

Use the TTF or WOFF2 in `compatibility-v016/final`. Open `full-016/specimens/Bunvale-review-specimens.pdf` for the core, separate expanded-Latin and combining-mark specimens. The core and expanded-Latin PNGs are also separate files. The PDF uses the actual embedded final WOFF2; PNG specimens use the actual final TTF.

This revision contains the complete verified **354-codepoint union**, plus four punctuation characters already present in Bunvale: U+201A, U+201E, U+2039 and U+203A. That is **358 mappings, 355 with ink**, including fourteen real zero-advance combining marks. SPACE, NBSP and SHY remain intentional blanks. An unencoded dotless-j helper supports accented j without adding another Unicode mapping. See `compatibility-v016/COVERAGE.csv` for every scalar, source and advance.

The additions are Ẁ/ẁ, Ẃ/ẃ, Ẅ/ẅ and Ỳ/ỳ, plus positioned combining marks. Capital Ľ now uses a Slovak side-caron. The other 335 previously mapped outlines and advances are unchanged, including all 52 selected alphabet bodies, the correct Latvian comma marks, ģ with its above comma, the other side-carons and dotless ĵ. No new image generation was used.

**Aesthetic choice still pending:** digits 2/3/4/5/7 and ß/ẞ are readable, heavy but deliberately quieter companions. Their construction has less of the alphabet's conspicuous swelling and flared terminals. They have not been declared fully approved for family style. The euro's heavy lower curve and the other authored extensions also remain available for user aesthetic review. No wholesale redesign was made merely to decorate already readable forms.

Intended use is display at **32px and larger**. Actual native TTF and browser WOFF2 proofs were inspected at 32, 64 and 96px. Body text and smaller sizes are not accepted. Static Regular metadata describes a visually heavy face; this is not a variable family. TTF and WOFF2 are provided, not CFF/OTF.

Both formats passed exact coverage, native outline/advance preservation, 1,623 kerning-pair checks, canonical decomposition checks and real mark-positioning tests. All fourteen marks have zero advance and GDEF mark classification. GPOS attaches them to bases and stacks; GSUB removes the original i/j dot when an above mark needs a dotless body. The 19 tested language and context samples render identically in NFC and NFD in Chromium. In particular, j + U+0326 + U+0301 and i + U+0326 + U+030B, including both reversed input orders, use dotless bodies with correctly positioned below and above marks. A scoped GSUB above-mark filter skips intervening below marks; ordinary selected i/j are unchanged. The unpublished 0.015 candidate failed this focused regression and was withdrawn before delivery. Latvian, Slovak and Welsh examples are supplied explicitly.

NBSP is genuinely blank and prevents a wrap where SPACE wraps. SHY remains hidden within an unbroken word and, at a browser wrap, displays a pixel-identical copy of Bunvale's authored hyphen. The earlier blanket statement that visible discretionary hyphens were unimplemented was too broad and is withdrawn. Both the preserved baseline and this final revision pass the actual browser test; its original blank mapping was retained.

The pinned Fontify source checkout remains unchanged at `249bf421e4be58bac8b42024fb42af264bd39838`. Fontify compiles the native vector bodies and components. The separately authorized fontTools compatibility step adds zero-advance mark mappings, attachment tables and the dotless-j context; it also supplies explicit 2500/-900 vertical metrics at 2000 UPM for tested accent stacks. This final file is **postprocessed compatibility output, not a direct unmodified CLI release**. Source-stage checks and final-binary checks are recorded separately. The actual pinned source/compiled geometry audits, unchanged final verifier and full 358-glyph/six-size review gate all pass.

The strict JSON front end cannot express the blank and zero-advance records, so `fontify-full358-api.json` is an explicit Project API declaration. `add_compat_marks016.py`, `compat_full_api.py`, the original component code, feature file and anchor manifest document reproduction. No shared compiler, verifier or security setting was changed. The helper's temporary U+0237 identifier appears only in a geometry probe; it is not present in the final cmap.

The repertoire is not a claim of every Latin language or every arbitrary sequence. Base anchors cover Latin letters and figures; singles and representative above/below stacks were checked, rather than unlimited stack heights or every possible pair. Keep enough line height for accents. No independent OTS sanitizer was run; FontTools, HarfBuzz, FreeType and real Chromium checks passed. Font/proof hashes and concrete results are in `compatibility-v016/QA_SUMMARY.json` and the final manifest.

Original vectors, prior revisions and prior private packages remain preserved. No commercial font software, system-font outlines or proprietary outline tracing was used. The generated source B and authored extensions have distinct provenance. No public repository integration, publication or sharing change occurred.
